Releasing

CI builds unsigned beta / prerelease artifacts. That is OK. Signing comes later via repository secrets — never commit certs or .env files.

Trigger

  • Push a tag matching v* (example v0.1.0-beta.2)
  • Or Actions → Release → Run workflow and pass the existing tag

The same tag also republishes GitHub Pages. Latest docs stay at the site root; a copy is published under /v0.1.0-beta.2/ (and older tags under /v…/). The header version menu switches between them.

Matrix

  • Windows x64 NSIS (ia32 skipped; Electron 43)
  • macOS universal DMG + ZIP when practical
  • Linux x64 AppImage + deb. Linux arm64 is off by default.

CSC_IDENTITY_AUTO_DISCOVERY=false so unsigned CI does not fail looking for a cert.

Signing later

Set these as GitHub Actions secrets when you have certificates. Do not put them in the repo.

  • CSC_LINK / CSC_KEY_PASSWORD — Windows and/or macOS .p12
  • APPLE_ID, APPLE_APP_SPECIFIC_PASSWORD, APPLE_TEAM_ID — notarization

Windows taskbar grouping uses app.setAppUserModelId('com.hawaldar.app'). That does not replace Authenticode. Until secrets exist, SmartScreen / Gatekeeper warnings are expected.

Local

cd hawaldar-app
scripts\dist.bat
